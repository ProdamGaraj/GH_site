# news-service

Хранилище новостей для Visual CMS: карточки ленты и страницы новостей.
Отдельный сервис по образцу `estate-service` — Node + Express + TypeORM, своя
БД `news` на том же Postgres (создаётся на старте), порт **5200**.

## Как новость попадает на сайт

1. Редактор пишет новость в админке CMS (раздел «Новости») и публикует её.
2. Владелец передеплоивает коллекцию новостей и страницы со списком —
   CMS берёт данные из `GET /api/news?full=1&lang=…` и собирает
   `/<язык>/news/<slug>/` по шаблон-странице «Новость».
3. После деплоя CMS сообщает сервису, что выкачено
   (`POST /api/admin/deployed`). Публичная лента отдаёт только выкаченное —
   карточка не ведёт на ещё не созданную страницу.

## Страница новости: шаблон-конструктор

У новостей нет фиксированной раскладки: hero (фото или слайдер), дальше блоки
в любом порядке — «текст», «фото + текст», «слайдер + текст». Шаблон-страница
в редакторе CMS одна:

- hero — карусель по `item.hero` (одно фото — без стрелок);
- тело — повтор по `item.sections`; внутри секции стоят заготовки всех типов,
  каждая под своим повтором: `$.text`, `$.photoText`, `$.sliderText`. У
  секции заполнен ровно один массив (0..1), поэтому рисуется только нужная
  заготовка. Условий в движке шаблонов нет — условность задаёт длина массива.

Текст секций — HTML (абзацы, жирный, курсив, ссылки, списки, h2/h3, цитаты).
Сервис чистит его при каждой записи по белому списку (`services/html.ts`) —
на сайт он вставляется как есть.

## Языки

База — ru, переводы uz/en (`news_translations`). На uz/en новость
публикуется, только если язык отмечен (`publishOn`) и перевод полный:
заголовок, анонс и текст каждой секции. Отметку нельзя поставить при неполном
переводе (400 с перечнем недостающего). Если перевод стал неполным позже
(добавили секцию), новость выпадает из языка до перевода, отметка остаётся.

## API

Внутреннее чтение (DataSource CMS, только внутренняя сеть):

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/news?lang=ru[&limit=N]` | карточки, от новых к старым |
| GET | `/api/news?lang=ru&full=1` | полные данные страниц — для коллекции CMS |
| GET | `/api/news/:slug?lang=ru` | страница новости; 404, если на языке её нет |

Публичное чтение (наружу через nginx, кэш 60 с):

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/public/news?lang&offset&limit&q&category&tags&tagMode&from&to` | порция ленты: `items`, `total`, `hasMore`, `tagModeTotals` |
| GET | `/api/public/news/facets?lang` | рубрики и теги с числом новостей, месяцы, границы дат |

Поиск: каждое слово должно найтись; сначала совпадения в заголовке, потом в
тексте. Теги: `tagMode=any` — с любым из выбранных, `all` — со всеми сразу.
Период: `from`/`to` — `YYYY-MM-DD` включительно, дни по Ташкенту.

Админ-API — заголовок `X-News-Token` (`NEWS_WRITE_TOKEN`; не задан — запись
запрещена):

- `GET/POST /api/admin/news`, `GET/PUT/DELETE /api/admin/news/:id`
- `POST /api/admin/news/:id/publish | unpublish | archive`
- `GET/POST /api/admin/categories`, `PUT/DELETE /api/admin/categories/:key` (так же `tags`)
- `POST /api/admin/deployed` `{ locale, slugs }` — отчёт CMS о деплое

Адрес новости — транслит заголовка; правится до первой публикации, потом
фиксируется (409). Рубрику или тег, которыми пользуются новости, удалить
нельзя (409) — их прячут флагом `hidden`.

## Разработка

```
npm install
npm test                 # юнит-тесты
npx tsc --noEmit
# сквозной тест API на настоящем Postgres (создаёт и удаляет временную БД):
NEWS_IT_DATABASE_URL=postgresql://cms_user:cms_password@localhost:5432/postgres npx jest api.integration
```

`sanitize-html` закреплён на 2.17.5: более новые тянут htmlparser2 v12 (только
ESM), который не загружается в Node 20.

Часть инфраструктуры — копии из estate-service (`config/ensureDatabase.ts`,
`migrations/runner.ts`, `middleware/*`, `services/Logger.ts`,
`services/mediaSlides.ts`): правьте обе копии.
